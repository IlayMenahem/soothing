\section*{Introduction}

A Gr\"obner basis is the standard tool for analyzing a system of polynomial equations $p_1 = \cdots = p_m = 0$, but computing one can be infeasible for large systems. In this document we therefore look for a weaker object: a Gr\"obner basis for a structured subvariety of $V(p_1, \ldots, p_m)$. Such a subvariety is obtained by adding optional structure hints, such as equations of the form $x_i = 0$, and by choosing one irreducible factor from each preprocessed polynomial.

The choice of factors is treated as a hitting-set problem. After factoring the polynomials, each polynomial gives a set of possible factors, and a minimal hitting set selects enough factors to cover all polynomials. Each selected hitting set, possibly together with structure hints, is checked by a Gr\"obner basis computation. When the check is unsatisfiable, a minimal unsatisfiable core is extracted and used to prune later choices, giving a CDCL-style search over candidate subsystems.

This approach is sound but incomplete: every solution of a selected subsystem is a solution of the original system, but solutions outside the chosen subvariety are not recovered. The theoretical question is how much dimension is lost. We argue that the loss comes from the added structure constraints, while factor selection can be made without further dimension loss when the factors are chosen jointly to realize a maximal-dimension intersection. Section~2 presents the general CDCL framework, Section~3 specializes it to polynomial systems, and the final claims state the corresponding subvariety and dimension properties.

\section*{The CDCL general framework}

In the general CDCL framework, we have a set of sets of constraints $C_1, \ldots, C_m$, and want to satisfy at least one constraint from each set.
We also have a set of constraints that we don't need to satisfy but can help the constraint checker to find a solution faster, or to state there is no solution. We call these constraints \emph{structure hints}.

\begin{algorithm}
\caption{CDCL framework}
\label{alg:cdcl framework}
\begin{algorithmic}[1]
    \Require A general input, and a set of structure hints $H$.

    \State Preprocess the general input to a set of sets of constraints $C_1, \ldots, C_m$

    \State Initialize $C = \emptyset$ an unsatisfiable cores set
    \State Initialize $S = \emptyset$ a solutions set

    \For{each minimal hitting set $HS$ of the sets of constraints $C_1, \ldots, C_m$ and a subset of the structure hints $F \subseteq H$}
        \If{$HS \cup F$ contains an unsatisfiable core in $C$}
            \State \textbf{continue}
        \EndIf

        \State Check if the minimal hitting set $HS \cup F$ is satisfiable
        \If{$HS \cup F$ is satisfiable}
            \State Add the solution to $S$
        \Else
            \State Extract a minimal unsatisfiable core $U$ from $HS \cup F$
            \State $C \gets C \cup \{U\}$
        \EndIf
    \EndFor

    \Return $S$ and $C$

\end{algorithmic}
\end{algorithm}

\begin{algorithm}
\caption{Extracting a minimal unsatisfiable core}
\label{alg:extracting a minimal unsatisfiable core}
\begin{algorithmic}[1]
    \Require A set of constraints $F$ that is unsatisfiable.

    \State Initialize $U = F$
    \For{each constraint $f \in F$}
        \State $U' \gets U \setminus \{f\}$
        \State Check whether $U'$ is unsatisfiable
        \If{$U'$ is unsatisfiable}
            \State $U \gets U'$
        \EndIf
    \EndFor

    \Return $U$

\end{algorithmic}
\end{algorithm}

The order of iteration over the minimal hitting sets and the structure hints should heuristically prioritize the easier to check sets first.

To specify a specialization of the CDCL framework to a particular problem, we need to define the following:
\begin{itemize}
    \item Structure hints for the problem
    \item The preprocessing of the input to an hitting set problem
    \item An order of iteration over the hitting sets and structure hints
    \item A checker for satisfiability of a hitting set
\end{itemize}

\section*{CDCL for system of polynomial equations}

Let us say we have a set of polynomials $p_1, \ldots, p_m$ over a field $k$, and we want to validate whether there exists a solution to the system $p_1 = \cdots = p_m = 0$.
We describe a CDCL-style algorithm that can be used to explore the space of possible minimal hitting sets of the polynomials.

\subsection*{Preprocessing the polynomials}

Given a set of multivariate polynomials $p_1, \ldots, p_m$, we perform the following preprocessing steps to simplify the system and prepare it for the CDCL algorithm:
\begin{algorithm}
\caption{Preprocessing the polynomials}
\label{alg:preprocessing}
\begin{algorithmic}[1]
    \Require A set of polynomials $p_1, \ldots, p_m$ over a field $k$.

    \State Interreduce the polynomials
    \State Factor the polynomials

    \Return $\{\{f_{1,1}, \ldots, f_{1,k_1}\}, \ldots, \{f_{m,1}, \ldots, f_{m,k_m}\}\}$ the sets of irreducible factors of each polynomial
\end{algorithmic}
\end{algorithm}

\subsection*{Minimal hitting sets of the factors}
A \emph{minimal hitting set} is a set $HS$ of factors such that $HS$ contains at least one factor from each polynomial's set of irreducible factors. the minimality means that no proper subset of $HS$ has this property.

\textbf{Order of iteration over the minimal hitting sets}: the order is from the simplest to the most complex to check for satisfiability. As a heuristic for this cost we use the B\'ezout bound $\prod_{f \in F} \deg f$: it bounds the number of isolated solutions and, for a regular cover, the solving degree of the Gr\"obner computation that decides satisfiability, whose Macaulay matrix grows with that degree. Iterating covers by increasing B\'ezout bound therefore tries the easy covers first.

\subsection*{Finding the unsatisfiable cores}
To check if a set of polynomials $F$ is satisfiable, we compute its reduced Gr\"obner basis $G$ with respect to a degrevlex order, using a signiture based algorithm such as F5, M4GB, or GVW.

\textbf{unsatisfiable core} is a subset $U \subseteq F$ of factors with no common zero, $V(U) = \bigcap_{f \in U} V(f) = \emptyset$; equivalently $\langle U \rangle = k[x_1, \ldots, x_n]$ is the unit ideal. We detect this from the reduced Gr\"obner basis of $U$, which equals $\{1\}$ exactly when $1 \in \langle U \rangle$.

Such a core is useable because the property is monotone under inclusion: if $V(U) = \emptyset$ then every hitting set $F' \supseteq U$ has $V(F') \subseteq V(U) = \emptyset$ and is therefore also unsatisfiable.

Given an unsatisfiable $F$, we extract a minimal core by deletion: consider its factors in turn, remove one, and recompute the Gr\"obner basis; keep the smaller set when it remains the unit ideal, otherwise restore the factor. After one pass over the $|F|$ factors every remaining factor is necessary --- dropping any one restores a solution --- so $U$ is a \emph{minimal} (inclusion-irreducible) unsatisfiable core. Minimality here is irreducibility, not minimum cardinality; a smallest core is NP-hard to find and unnecessary for soundness of the pruning.

If we were to select an hitting set $F$ that is contained in a previously found satisfiable hitting set $F'$, then $V(F) \supseteq V(F') \neq \emptyset$ and $F$ is also satisfiable. This is the dual of the unsatisfiable core property, and can be used to prune the search space in a similar way.

\subsection*{Using structure hints}

In some problems such as in physics, we prefer solutions which have certain structure.
certain structures can be encoded as additional polynomial constraints, and can enable faster computation of the Gr\"obner basis.

\begin{itemize}
    \item Sparsity constrains can be encoded as the equation $x_i = 0$ for some variables $x_i$
    \item Affine constraints can be encoded as $a_1 x_1 + \cdots + a_n x_n = b$ for some constants $a_i, b$
\end{itemize}

When allowing for structure hints, the algorithm can be modified to consider minimal hitting sets for the original polynomials with an addition of any subset of the structure polynomials.
