The dense $n=7$ run failed while constructing the first recursive child:
the expanded Singular program exceeded the operating system's command-line
argument limit.  This is an implementation error, not an UNSAT result or a
timeout.  We also tried M4GB, F5, GVW, and F4 on this system.  These
backends execute in-process; after a per-hitting-set timeout their non-cancellable
worker threads continued alongside the recursive children until the process
was killed under memory pressure.  Singular remains preferable for the hard
rows because its external worker can be terminated.  The Cyclic-7 run
exhausted all useful splitting variables on one route and therefore returned
one unresolved branch.
